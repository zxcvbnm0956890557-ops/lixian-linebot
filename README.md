# 李鮮 LINE 訂單機器人（Codex 測試版）

這是一套全新的測試專案，不會讀寫舊機器人的資料，也不會碰原本的 Google 表單或正式訂單表。

## 客人以後怎麼下單

客人直接在李鮮官方 LINE 傳送資料，不必照固定順序，也可以拆成數則訊息：

```text
10斤1
江珈儀
0978006578
雲林縣斗六市崙南路128號
```

或：

```text
5斤20
台北市中山區松江路410號17F，0979869999，李明勳
管理員代收
```

機器人等待 30 秒，合併同一位客人剛傳的訊息，再做一次完整辨識。系統不靠欄位順序，而是分別檢查手機、地址、姓名和箱數。

辨識結果只有在以下項目全部通過時才會進入測試訂單表：

- 姓名不能像電話或地址
- 手機必須是 `09` 開頭共 10 碼
- 地址必須含縣市與路、街、巷、號等必要資訊
- 必須有 5斤或10斤箱數
- AI 信心必須至少 0.80
- 有歧義時一律列為「待人工確認」，不自動猜答案

## 送禮訂單

系統把三個角色分開保存：

- 訂購人：在 LINE 下單的客人
- 收件人：真正收到水果的人
- 黑貓寄件人：一般為「李鮮」，送禮時才改成客人指定姓名

送禮時只改黑貓寄件人姓名；寄件電話與寄件地址仍固定使用李鮮資料，不會跟著變動。

## 支援的 7 種黑貓件規格

1. 5斤1箱
2. 5斤2箱
3. 5斤4箱
4. 10斤1箱
5. 10斤2箱
6. 5斤1箱＋10斤1箱（同一件）
7. 5斤2箱＋10斤1箱（同一件）

例如 `5斤20` 會自動拆成五件 `5斤4箱`。產出的黑貓 CSV 為 27 欄、UTF-8 BOM、全部欄位加雙引號。

## 現在完成的部分

- LINE Webhook 簽章驗證與快速收件
- 防止 LINE 重送造成重複訂單
- 多則訊息合併
- AI 結構化辨識與規則式二次驗證
- 訂購人、收件人、寄件人分欄
- 7 種規格拆件與黑貓 27 欄 CSV
- Google 測試試算表寫入模組
- 每晚 9 點統計模組
- Render 常駐部署設定，不使用免費喚醒網站
- 預設 `DRY_RUN=1`，不會回覆正式 LINE

## 還不能直接上正式的部分

正式啟用前仍需填入新的 LINE Messaging API 憑證、Google 測試表服務帳戶，以及確認黑貓提供的正式 API 權限與文件。黑貓網站登入後自動上傳、取得正式託運單 PDF，不能只靠猜測網址；在官方 API 權限確認前，本版只安全產出可匯入黑貓的 CSV，不會操作正式出貨。

因此目前正確階段是「獨立測試版」，不是已經接上正式 LINE 的成品。

## 本機安裝與測試

需要 Python 3.11 以上：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
pytest
```

複製環境設定範本：

```bash
cp .env.example .env.local
```

真正的密鑰只能放在 `.env.local` 或 Render 的 Secret，不可貼進程式、README 或群組。

啟動本機測試：

```bash
python app.py
```

健康檢查：`http://localhost:5000/health`

## 測試轉正式的順序

1. 新建一個 LINE 測試 Provider／Channel，不沿用舊機器人 Token。
2. 建立一張全新的 Google 測試表，只分享給新的服務帳戶。
3. 在 Render 建立付費常駐服務並保持 `DRY_RUN=1`。
4. 用測試 LINE 傳至少 20 種亂序、分段、送禮及錯誤資料。
5. 人工逐筆核對 Google 測試表和黑貓 CSV。
6. 取得並驗證黑貓正式 API 權限，先跑測試單，確認 PDF 格式。
7. 全部驗收後才把 Webhook 切到官方 LINE，最後才改成 `DRY_RUN=0`。

## 安全提醒

舊機器人的 Token 和憑證應全部撤銷並重建。程式不會把 OpenAI、LINE 或 Google 金鑰寫入日誌；`.gitignore` 也已排除 `.env.local`、資料庫和匯出檔。
